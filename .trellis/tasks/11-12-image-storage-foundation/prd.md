# 图片存储基础与本地持久化

## 目标与来源

完成父任务 `11-12-local-media-retention` 的存储基础，使图片在不配置 S3 的测试部署中可生成、上传、查看和下载，并且所有受管理写入可计量、可追踪。拥有父 R1，及 R5/R6/R7/R9 的基础部分；父 PRD 的图片范围、保护规则和视频排除是共同约束。

## 前置条件

- 父任务最新最终规划获得用户明确实施批准；本子任务无其他子任务前置。
- 只在本子任务被 `task.py start` 激活后派发实施。批准整份计划后，后续子任务按质量门禁推进，不重复要求创建任务授权。

## 需求

- S1：统一登记生成图片、普通参考图和 Canvas 导入的逻辑身份、物理文件、实际/预留字节与引用；业务行被删除仍保留可核实的物理清单。
- S2：本地文件使用持久化卷和明确位置身份，Node/Go 在共享目录读写；保留 S3 适配和每个历史位置的区分。
- S3：全站 5,000,000,000 字节 gate 包含并发预留；上游前申请有界输出预算、写入后按真实长度结算，重复提交不重复占用。
- S4：建立生成结果/参考图/保存画布/任务输入/精选审核/站点封面的引用保护；保留 Canvas 原图账户限制、长期任务根和七天宽限。
- S5：稳定 HTTP(S) 图片读取兼容网页、优化器、代理下载、图生图和外部 b64 输出；内部读取通过已登记身份，任意远端 URL 仍使用原校验。
- S6：LOCAL Canvas 导入使用真实 provider；保留旧原图 ID 和原始 S3 tuple，更新存储/GC 能力修订、schema 校验及旧 Worker 隔离。
- S7：保持现有 v0/v1 扣费、退款与未知 handoff 语义；不把视频文件或视频专用封面纳入上述流程。

## 验收标准

- [x] S-A1：隔离环境未设置 S3 凭据时，普通图片、上传参考图和 Canvas 导入完整读写；进程/容器重建后原字节可读。对应父 A1/A8。
- [x] S-A2：两个 Node/Go 写入者竞争最后额度，超过 2GiB 的总数无溢出；幂等重放和从预算到物理计量不会双算。对应父 A4。
- [x] S-A3：上游 b64 大图、超额返回张数、内部 count 越界有明确失败；容量不足在上游前拒绝，v0/v1 原退款规则保留。对应父 A10。
- [x] S-A4：新引用与资产状态协调；Canvas 旧输入根、七天宽限及账户额度保持，生成输出来源不会被误当永久输入根。对应父 A5。
- [x] S-A5：写入成功但业务提交失败、部分多图失败和未知回执仍留有可对账文件清单；真实删除尚未实现时不能虚释放额度。对应父 A6。
- [x] S-A6：新 Node 拒绝旧存储/GC Worker；卷错配、不可写目录不能报告 ready，embedded 探针不依赖 Next 启动。对应父 A8。
- [x] S-A7：S3 模式回归及视频/第三方资源排除负例通过。对应父 A7/A9 的基础。

## 不在本子任务内

管理员清理页面、定时/容量实际删除和历史批量迁移分别交给后两个子任务。额度不足在本阶段明确拒绝，不假装未来清理器已经存在。视频及其专用封面始终不在父任务范围。

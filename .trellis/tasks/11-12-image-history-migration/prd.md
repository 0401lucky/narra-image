# 历史图片登记与 R2 迁移

## 目标与来源

完成父任务 `11-12-local-media-retention` 的 R8，并把 R5/R6/R7 应用于历史图片：原链接与画布在应用内可继续使用，旧 R2 图片可经过盘点、复制校验和可恢复切换迁到本地，已有用量不被遗漏或虚报释放。

## 前置条件

`11-12-image-storage-foundation` 和 `11-12-image-retention-management` 均完成本阶段依赖的验证。统一存储/引用/额度及物理删除执行器可调用后再进入迁移。本子任务不重新定义另一套复制计量或删除流程。父整体计划获准且本任务被激活后实施。

## 需求

- H1：盘点数据库可识别的历史生成图片、普通上传参考图、Canvas 导入及其引用；核实源位置、真实大小和对象身份，未知/第三方来源单独标记。
- H2：历史业务 ID、Canvas 上传身份和原始存储 tuple、冻结的任务输入保持稳定；应用内精确旧 URL 能解析当前可读副本。
- H3：提供默认 dry-run、显式 apply 的迁移工具；复制、校验、切换位置和源退休都有可追踪状态，失败后可以恢复。
- H4：目标写入遵守全站额度和并发预留；源/目标同时存在时都计量。默认保留源；只有显式选择并通过替代副本/读取兼容/在途检查后才删除源。
- H5：保护未知写入、版本异常、活动删除/迁移状态和全部既有输入根；迁移同内容副本不把逻辑图片或账户原图额度删掉。
- H6：提供 embedded 与同宿主机 dedicated 的持久化、启用、旧 Worker drain、迁移/回滚说明，执行父级完整集成验证。
- H7：视频、视频专用封面、未知 bucket 对象和任意第三方图片不进入本轮迁移/自动删除范围；站外原 R2 URL 在删源后不保证继续有效。

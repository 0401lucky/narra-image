# 历史图片登记与迁移设计

采用父任务 `../11-12-local-media-retention/design.md` 第 2、5、7、8 节和前两个子任务已验证的接口。只增加历史发现、复制编排和部署流程，不另写一个绕过容量/引用的清理器。

## 盘点与引用接管

从业务记录中发现候选并显式绑定已确认源 location；生成图片的 storageKey 缺少原 endpoint/bucket，不能只套当前 S3 配置。只有可核实的源对象才登记为物理副本。普通参考 URL、旧 result 输入、保存场景、展示/审核及当前封面要映射精确受管理身份，未知保持可读且不可自动回收。

历史记录按稳定游标分批读取，盘点有可恢复状态与范围摘要。重复登记由物理唯一性和 payload identity 保证幂等；不能靠 bucket 前缀删除来“消除重复”。既有 UNKNOWN/DELETING/版本异常按真实状态接管，不能强行标为 READY。

核实已经存在的物理对象是独立 observed-object 登记动作：它没有新 PUT，不能伪装成 INPUT/COPY 预留或借 C1 窄 backfill 入口跳过来源证明。历史真实字节可能已超过上限，登记必须如实增加已用量并报告超额；后续复制和新增写入仍受原额度 gate 限制。登记与精确别名/历史根的接管需要在可回收之前形成一致保护。

## 迁移协议

`计划 → 目标预留 → 复制 → 内容校验 → 活动副本切换 → 保留源 / 显式退休源`。每步都有原始身份、预期源/目标、token 与状态，复制和对象 IO 不持有长业务事务。精确字节与 SHA256 一致才允许当前读取位置切换。

冻结输入字符串不改写：受管理旧 URL 由别名解析器返回当前副本；Canvas 原始 tuple 作为来源事实保留。已保存素材 ID 和 roots 稳定，迁移仅增加物理副本，不让账户原图数翻倍。

源退休复用 C2 已实现的 `SOURCE_RETIREMENT` 资格：目标为同一逻辑图片的校验 READY 当前副本、读取兼容完成、无依赖旧副本的在途操作。它不是整张图片的 RETENTION 删除。默认保留源，显式申请的源删除结果按确切回执计量；只复制不叫释放 R2 空间。

所有副本及在途目标预留纳入父级 5GB 管理额度；复制阶段需要余量。没有余量时先回收合法候选或由管理员明确调整限额，不能静默免计迁移。站外复制的旧 R2 URL 受源保留/域名控制影响，应用内别名不提供站外重定向保证。

## 部署与验证

提供默认 dry-run 的 CLI，与现有 Go 运维工具共享配置读取和输出风格。先准备匹配 schema/Node/Worker、drain 旧执行者并绑定真实图片卷，再盘点、启用策略和切换写入。新旧 GC 不滚动混跑。回滚只选择仍可读的副本，存在新 revision/LOCAL 或未完成动作时禁止启动旧 Worker。

最终在一次可追溯的当前代码快照上执行完整新/旧数据与两种拓扑验收。真实 R2 用量、用户部署和站外旧链接属于后续真实环境事项，不能从模拟存储通过推断已经迁移完成。

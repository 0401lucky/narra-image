# 图片清理与管理员存储管理

## 目标与来源

完成父任务 `11-12-local-media-retention` 的 R2–R7/R9：管理员在网页查看真实用量、预览并确认清理，后台按时间或容量自动回收符合规则的图片，并在历史页面识别已清理文件。

## 前置条件

`11-12-image-storage-foundation` 的统一清单、引用/状态、额度预留、本地/S3 读写与能力修订已经通过本阶段需要的专项验证。共享模型与错误接口可用后再开始本子任务，不依赖目录树顺序猜测先后。父最终整体规划批准覆盖此子任务，进入实施仍须满足前置质量门禁并激活本任务。

## 需求

- C1：管理员页面显示已登记用量、未物化预留、5GB 上限、文件数量、可清理量、待盘点情况与最近执行结果。
- C2：支持策略版本化修改、一键预览/确认/进度查询；普通用户不能执行全站管理。确认范围不包含预览之后的新图片。
- C3：定时开关默认关闭；开启时初始每 24 小时清理超过 30 天的可清理图片，参数可改。浏览器关闭不影响后台任务。
- C4：容量不足时从最旧可清理图片回收满足预留所需的空间；年龄阈值可让位于容量清理，保护规则始终优先。
- C5：精选/审核中、有效画布/任务/站点封面引用、写入与迁移中状态受保护；原图七天宽限及永久输入根保持。受保护内容占满时明确拒绝新增。
- C6：一套有恢复能力的执行器处理手动、定时、容量触发；重复请求、多 Worker、删除失败和 ACK 丢失不重复减量。
- C7：文件确认删除后保留媒体/任务历史，显示“图片已清理”，阻止下载/复用；不修改生成和计费事实。

## 验收标准

- [x] C-A1：管理员完成统计→修改策略→预览→确认→查看结果；未登录/非管理员请求被服务端拒绝。对应父 A2。
- [x] C-A2：浏览器关闭、重复确认、多 Worker 和进程重启后仍是同一项可恢复任务，已释放字节只计算一次。对应父 A3/A6。
- [x] C-A3：接近上限时按 `(createdAt,id)` 回收足够的允许对象；保护占满返回容量不足。对应父 A4/A5。
- [x] C-A4：预览后变成精选、被保存画布/任务引用或成为封面的图片被跳过；上传、迁移及原图七天宽限不被绕过。对应父 A5。
- [x] C-A5：本地/S3 实际文件删除成功才减用量；失败/UNKNOWN、旧 PUT 未定或版本状态异常保留计量和恢复状态。对应父 A6/A7。
- [x] C-A6：历史普通作品、生成会话、画布引用解析与外部查询能识别清理态，提示词/终态/余额保留。对应父 A6/A10。
- [x] C-A7：视频、视频专用封面、任意第三方图片和未登记对象不进入统计承诺与清理候选。对应父 A9。

## 不在本子任务内

不执行真实桶清理，也不负责历史批量纳管/迁移；这些操作由 C3 工具和用户后续部署流程处理。可复用的迁移源副本删除资格与执行接口属于统一清理器，迁移命令编排属于 C3。

# 图片清理与管理设计

以父任务 `../11-12-local-media-retention/design.md` 第 2、5、6 节为共享契约。依赖 C1 的清单、引用、预留和物理状态；本子任务不复制另一个用量统计源或删除器。

## 执行流程

`预览/定时/容量需求 → 持久任务 → 短事务复核引用与领取 → 事务外精确文件删除 → token CAS 完成 → 更新实际物理计量 → 必要时完成逻辑图片 tombstone`。

手动确认绑定 previewId、policyVersion、requestId 和有界候选快照。年龄和容量模式共用 eligibility；容量选择按时间最旧优先，只满足此次预算缺口。等待清理不持有额度或生成业务事务。

逻辑清理阻止新引用并保留原有根/七天 guard；迁移源退休只允许有同内容已验证活动副本、旧读取兼容与在途检查已通过的冗余副本。两类操作使用同一个物理 token/executor，不能由旧 Canvas GC 再删一次。

### 历史回填关联的保护接缝

C1 保留的旧图片 backfill 可为既有 `GenerationImage` 新绑定 `mediaAssetId`。这个 UPDATE 不会重放早先保存的 Canvas scene 或历史 run 输入的触发器。因此 `ImageReference` 为空不能单独证明没有历史引用。C2 在开放任何删除 claim 前必须补齐绑定桥接/既有根，并在候选判断与执行复核中保护原 scene/run 事实；不能把此安全前置推迟到 C3 历史盘点。真实 DB 回归须包括“先保存旧 result/提交旧输入，再回填关联，之后尝试清理”。

## 状态与调度

- Worker 生命周期中运行有界调度，数据库时间及持久 nextRunAt/lease 控制多实例与重启；一轮成功或失败都保存状态和实际释放量。
- 中断/租约过期不丢候选，下一次执行从持久 cursor 恢复。删除失败和 UNKNOWN 继续计量并退避；已结束的对象不因任务重放再减一次。
- 后端变更、卷错配、S3 版本/位置未知会使相关对象不可领取，不能回退为未验证的删除成功。

## 网页与 API

管理入口 `/admin/settings/storage` 接入现有总览卡片和子导航。按父设计的 `/api/admin/storage`、policy、preview、cleanup、jobs API 分层：服务端鉴权/校验，server-only 服务维护语义，client 只展示与发命令。

界面并列展示用量/预留/额度、待盘点范围、可释放量、策略开关和最近任务。删除确认展示“预计”，结果展示“实际”；部分完成、失败和被保护跳过有明确反馈。轮询从任务 ID 恢复，重载页面不重新提交删除。

清理状态进入共享 DTO 和 serializers，作品、会话、画布解析与公开 API 按已有权限返回可用性。文件失效不清除提示词/任务，也不依赖 `<img onError>` 才发现已删除。不会把新管理字段加入非作者可见的敏感数据。
